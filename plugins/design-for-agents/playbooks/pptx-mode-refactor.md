# 既存資料のリファクタ

## 状況

既にある資料を直す。**改修は主張を保ち、形を変える作業である。**
主張が変わるものは改修ではなく書き直しであり、著者の同意が要る。

両側に失敗がある。

- **化粧直し** — 何も論じていない資料の色と書体だけを変える。
  見た目は良くなり、誰も説得されない
- **黙った書き直し** — 整えるついでに主張を「良く」する。
  著者は自分がしていない主張を発表し、質問に答えられない

**醜いのではなく間違っているスライドは、そう言って主張は残す。**
著者が決めるべき指摘として一覧に出す。

## 手順

診断は5回に分けて読む。混ぜると化粧直しになる。各回で所見を書き出してから次へ進む。

1. **タイトルだけを読む。** 全タイトルを順に並べ、1つの文書として読む。
   1つの案件を論じているか。筋が切れるのはどこか。体言止めのタイトルは
   そもそも論を運べないので、全て印を付ける
2. **1枚1主張を見る。** 主張が2つあるスライドと、1つも無いスライドに印を付ける
3. **証拠を見る。** 全ての数値に出所があるか。各グラフはタイトルの主張を
   支えているか、そばに置いてあるだけか
4. **構造か装飾かを見る。** 全ての図・箱・矢印・SmartArt に情報テストを当てる
5. **形を見る。** ここで初めて、文字サイズ・整列・色数・帯・密度・コントラスト・
   代替テキストを見る

## 決め打ち値

修正の順序は次のとおり。後の項目は、前の項目が壊れている資料では無駄になる。

| 順 | 所見 | 直し方 |
|---|---|---|
| 1 | 支配的な主張が無い | 骨格から作り直す。著者の同意を取る |
| 2 | 体言止めのタイトル | 主張文に書き直す |
| 3 | 主張が2つ、または0のスライド | 割る、まとめる、落とす |
| 4 | 証拠と出所の無い主張 | 出所を足すか、主張の格を下げる |
| 5 | 装飾的な図、SmartArt、埋め草の図形 | 消すか、構造を符号化して描き直す |
| 6 | 問いに合わないグラフ、3D、分解円 | 選び直す |
| 7 | 密度超過、縮められた本文 | スライドを割る。縮めない |
| 8 | 装飾（帯、グラデーション、影、色数） | 消す |
| 9 | アクセシビリティ | 納品前に直す |

**その場で直すか、作り直すか**

| 状況 | 選ぶ |
|---|---|
| 数枚の修正で済み、スライドマスターとレイアウトが生きている | その場で直す |
| 組織のテンプレートで、内容だけが悪い | その場で直す。または同じテンプレートに詰め直す |
| 内容が白紙スライドのテキストボックスに置かれている | 作り直す。直しても病気が残る |
| 主張の構成そのものを組み替える | 作り直す。並べ替えは文章の作業であってスライドの作業ではない |
| 全体の3分の1以上に構造的な修正が要る | 作り直す |
| 原本を同じファイルで返す必要がある（変更履歴、査読中） | その場で直し、残った負債を書き添える |

作り直すとは、内容を仕様に抽出し、主張を文章として直し、新しいファイルを
描画することである（`pptx-build` の `extract_deck.py` → 編集 → `build_deck.py`）。
**文章は主張を変えるのが安く、スライドは高い。**

## よくある失敗

- **著者の言い回しを変える。** タイトルを主張文に締めるのは範囲内。
  何を主張しているかを変えるのは範囲外
- **数値・単位・但し書き・出典を落とす。** 同じ数値が2箇所で食い違うなら、
  どちらかを選ばずに矛盾として報告する
- **発表者ノートを消す。** スライドに載っていない半分の主張がそこにある
- **黙ってスライドを消す。** 削除は内容の判断である。提案し、実行しない
- **割ったのに主張が重なる。** 2つの新しいタイトルは、どちらも真で、
  かつ重ならなければならない
