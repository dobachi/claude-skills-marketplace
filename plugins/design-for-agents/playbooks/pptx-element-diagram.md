# 構造図のスライド

## 状況

図は、文章では表せない構造を符号化するためにある。
**符号化していない図形は、箇条書きに衣装を着せたものである。**

## 手順

1. **情報テストを通す。** どの構造を符号化するかを名指しし、図形と矢印を
   消したとき何が失われるかを答える。「何も」なら描かない
2. **図の種類を選ぶ。** 分岐があるなら流れ図、担当をまたぐなら
   スイムレーン、階層なら木、2軸の区分なら 2×2
3. **抽象度を1つに決める。** 1枚に1つのズームレベル
4. **矢印の意味を1つ決める。** データの流れ／依存／呼び出し／時間 から1つ
5. **凡例を図の中に置く。** 矢印の意味と、線種・色の意味
6. **箱に定義を入れる。** ラベルだけでは読み手はそれが何か分からない
7. **境界で囲む。** 意味のある境界（配置、信頼、所有、区画）だけを枠にする
8. **代替テキストを書く。** 図の種類ではなく、そこから言えること

## 決め打ち値

- **1スライドの図**: 1つ
- **図形**: 四角。意味を持つ記法（既知の図法）でない限り、六角形・雲を使わない
- **色**: 4枠。グループ分けは境界の枠で示し、色を増やさない
- **同じ階層の箱**: 同じ大きさ
- **SmartArt**: 使わない（例外は `pptx-diagram-smartart-none`）
- **元ファイル**: Mermaid か PlantUML で持ち、デッキと一緒に版管理する

## よくある失敗

- **箱と矢印を置くこと自体が説明になったつもりになる。** 情報テストを飛ばしている
- **矢印の意味が混ざる。** 1枚の中でデータの流れと依存が混在すると、
  読み手はどの規則で読むか決められない。これは誤りであって細かい指摘ではない
- **抽象度が混ざる。** 「データベース」と「顧客の行動」を並べない
- **同じ重要度の箱を違う大きさで描く。** 無い階層があるように読める
- **空白を埋めるために図を足す。** 余白は空けているのであって、空いているのではない
