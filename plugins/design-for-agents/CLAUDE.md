# design-for-agents — 作業指示

## このプロジェクトは何か

人間向けに書かれたデザイン知を、**AIが迷わず引ける形**に組み直した参照体。
価値は知識の新しさではなく、**AIが誤らない引き方ができること**にある。

**まず [CONCEPT.md](CONCEPT.md) を読むこと。** 設計原理・書式・階層・ロードマップは
すべてそこに書いてある。以下はその要約と、作業上の決めごと。

## 作業規約

1. **すべてのファイルが CONCEPT.md 第2節の9つの構造要件を満たすこと。**
   満たせないものは追加しない。
2. **「検討せよ」「適切に」「必要に応じて」を書かない。** 決め打ちの値を書く。
   決められないなら、それは項目としてまだ書けていない。
3. **同じ内容を2か所に書かない。** 上流はここ、下流はスキル側。重複は必ず崩れる。
4. **各ルールに出典を付ける。** 出典が出せないものは HOUSE（このリポジトリの決め）と
   明示し、外部規範のふりをさせない。
5. **`done_when` は検出器互換の書式で書く。** v0.2 で `check: manual` を
   `automated` に昇格させるとき、書き直しにならないようにする。
6. **`floor`（下限）を必ず添える。** 削除によって条件を満たせる検証条件は無効。
7. **公開リポジトリである。** 個人名を含む絶対パス、社内固有の情報、
   未公開資料からの引用を書かない。他リポジトリは相対パスで指す。

## 合流の経緯（2026-08-29）

独立リポジトリ `dobachi/design-for-agents` として作り、subtree で取り込んだ。
分けたままにしなかった理由は2つ。

1. `install.sh` の cross-agent symlink は `plugins/*/skills/<name>/` を単位に
   しており、**独立リポジトリでは Codex / Gemini / agy に配れない**
2. マーケットプレイス側に CI と `release_check.sh` があり、こちらの `lint.py` と
   合わせて規約の番人が2重になる

失ったのは独立した URL としての引用アンカーだけである。
