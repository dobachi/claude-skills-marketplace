# 検出器

出典付き調査レポートの検証。**1目的・依存なし・編集して使う**小さなスクリプト群。
`check_doc.py`（1ファイル5目的の試作）を 2026-08-09 に分割したもの。

## 一覧

| スクリプト | 何を見るか | 引数 |
|---|---|---|
| `forbidden_phrases.py` | 執筆経緯（「【訂正】」「初版」等）の混入 | `<file>...` |
| `refs_integrity.py` | 本文の `[S-xx]` と出典表の対応（未定義・未使用・重複） | `<file>...` |
| `declared_counts.py` | 文書が自分で申告した件数と実測の一致 | `<file>...` |
| `citation_presence.py` | 数字を含む断定文に引用が付いていない箇所（ヒューリスティック）。**この検査が要求した参照の行数も出す** | `<file>...` |
| `distribution.py` | 出典の集中度・Tier構成・未照合率（1件ずつでは見えない欠陥） | `<file>...` |
| `no_regression.py` | 編集前後で根拠の量が減っていないこと | `<前> <後>` |
| `build_artifacts.py` | ビルド生成物の実体（0バイト・必須ファイル・陽性対照） | `[生成dir]` |
| `matrix_freshness.py` | 測定日つきの**腐る資料**が期限を過ぎていないか | `<file>...` |
| `span_verify.py` | **ループの外で回す。** 引用が出典の原文に実在するかを照合し、台帳に落とす | `<file> [台帳]` |
| `spans_verified.py` | 台帳が文書の参照を覆っているか（ゲートに入れる側） | `<file> <台帳>` |
| `applicability_report.py` | **判定しない。** 各検出器がこの文書に噛むかを数字で見せる（フェーズ0 の入口） | `<file>...` |
| `_template.py` | **ひな型。** コピーして冒頭の編集点だけ書き換える | `<file>...` |
| `test_detectors.sh` | 上の期待値の表を走らせる | なし |

終了コードは **0=OK / 1=NG / 2=引数エラー**。ループの停止条件にそのまま使える。

**例外が1本ある。** `applicability_report.py` は 1 を返さない（0=出力できた / 2=引数エラー）。
噛んでいるかを決めるのは人であり、閾値も適否も機械が決める話ではないためである
（4階層の第3層＝「数字を出す。閾値は人が決める」に属する）。

## 作法（守らないと「編集して使う」が成立しない）

| 制約 | 理由 |
|---|---|
| 1ファイル1目的 | 目的が複数だと編集点が分からない |
| 標準ライブラリのみ | 環境差で動かないと編集する気が失せる |
| 30〜120行 | 読み切れる長さ。超えたら分割の合図 |
| 設定ファイルを持たない。定数は冒頭にベタ書き | そこが編集点だと自明になる |
| 出力に「保証しないこと」を含める | 編集した人が限界を引き継げる |
| 終了コードで判定できる | ループの停止条件に直結 |

共通処理を切り出したくなるが、**しない**。1ファイル単独でコピーして書き換えられることが
依存なしの実体であり、共通モジュールを作った時点で成立しなくなる。正規表現の重複は許容する。

## 検出器は2種類ある

**どちらかで、規則の掛かり方が変わる**（ARCHITECTURE.md §3）。ひな型の `KIND` に書く。

| `KIND` | 中身 | 実例が要るか | 例 |
|---|---|---|---|
| `"spec"` | 仕様から書ける判定。対応関係・数の一致・存在確認 | 不要。先に書いてよい | `refs_integrity` / `declared_counts` / `build_artifacts` |
| `"example"` | 実例からしか書けない判定。ヒューリスティック・除外リスト・閾値 | **必須** | `forbidden_phrases` / `citation_presence` / `distribution` |

**増やし方**: `example` は**実際に取り逃した欠陥からのみ**追加する。先回りして書いた項目は
使われないか、起きたときには形が違う。`forbidden_phrases.py` が価値を持つのは、実際に
11箇所出荷しかけたから。ひな型の `ORIGIN` が空のまま `KIND="example"` で回すと exit 2 で落ちる。

`spec` にこの制約は掛からない。ただし**実物に当てる工程（書式の採取と 3種の期待値）は飛ばせない**。
飛ばした結果が下の `REQUIRE_APPLICABLE` である。

## 第2層（引用が原文に実在するか）は2段に分ける

照合はネットワークに触るので、遅く・非決定的で・失敗しうる。ゲートに入れると
「全部走らせても秒で終わる」前提が崩れ、取得失敗の扱いが fail-open か
「ネットが落ちたら止まる」の二択になる。**だから照合はループの外で済ませ、ゲートは台帳を見る。**

```bash
python3 span_verify.py 対象.md /tmp/gate/doc.verified   # ループの外。たまに回す
python3 spans_verified.py 対象.md /tmp/gate/doc.verified # ゲート。秒で終わる
```

**台帳はループの書き込み範囲の外に置く。** 満たす側が「済」と書けてはいけない。
検出器を read-only にするのと同じ理由である。

**言い換えだけの参照は対象外。** 照合する原文の断片が無く、参照が主張を支えるかは
第4層（主観）である。件数は必ず出るので、そこが見ていない範囲だと分かる。
実測（実験3）: 参照43件のうち引用を伴うのは15件、**28件は言い換えだけ**だった。

## ゲートを組む前に噛み合いを見る

```bash
python3 applicability_report.py 対象.md
```

どのマーカー（出典表・参照記号・申告行・引用行・引用スパン）が何件あり、
**どの検出器が空振りするか**を出す。判定はしない。

これが無くて実際に間違えた例が3つある。
出典表も参照記号も0件の文書で素通りを合格と読んだ（§7.1）、
`^>` が0行の文書に `sed` をかけて無変更を「変えたのに通った」と読んだ（§7.2）、
候補8件が全て偽陽性だった（実験3のフェーズ0）。

## 前提を持たない文書で落ちること

検出器は書式に噛んで初めて機能する。噛んでいなければ、**0件は合格ではない**。

実測（2026-08-11）: `[S-xx]` 記法を持たない4文書に当てたところ、`refs_integrity` と
`declared_counts` が 0件 → exit 0 を返した。出典が1件も無い文書を素通ししていた。
`no_regression` は5指標のうち4つが常時ゼロになり、行数しか見ない状態に退化していた。

ひな型の `REQUIRE_APPLICABLE = True`（既定）がこれを塞ぐ。緩めるなら、
「この文書は前提を持たない」と人が確認した記録を残すこと。

## 単独で停止条件にしない

理由は2つある。

1. どれも**消せば満たせる**。`no_regression.py` を併用して下限を添える
2. **1本を満たすと別の1本が落ちる。** 実験2では `citation_presence` を満たした結果
   `declared_counts` が壊れた（設計への示唆 §11）。ループの各周回で全部を走らせ、
   「全部 OK」を終了条件にする。実行コストは秒なので理由がない

```bash
# Claude Code: ツールがループを持つ
/goal python3 detectors/forbidden_phrases.py report.md が OK になるまで直して、5回で諦めて

# Codex / agy: 呼び出し側がループを持つ
cp report.md /tmp/base.md
for i in $(seq 5); do
  python3 detectors/forbidden_phrases.py report.md \
    && python3 detectors/no_regression.py /tmp/base.md report.md && break
  codex exec "NG を直して。消して通すのは禁止"
done
```

検出器は**ループの書き込み範囲外**に置く。同じ木の中にあると、最短経路が
「検出器を書き換える」になる（HANDOVER §2.4-2）。

## テスト

`fixtures/` は**架空の調査レポート**（`clean.md`）と、そこから機械的に作った欠陥版。回帰の確認に使う。

| fixture | 期待 |
|---|---|
| `clean.md` | 正常版。全検出器が OK を返す |
| `with_history.md` | 執筆経緯を注入 → `forbidden_phrases` NG |
| `broken_ref.md` | 未定義の `[S-99]` を注入 → `refs_integrity` NG |
| `uncited.md` | 参照と引用を除去 → `citation_presence` NG |
| `declared_mismatch.md` | 申告値を改変 → `declared_counts` NG |
| `quotes_emptied.md` | 引用の中身を空に（行数は不変）→ `no_regression` NG |
| `no_markers.md` | 出典記法なし → 前提を持つ検出器が「測定できない」で NG |
| `spans_doc.md` + `spans_ledger_{ok,ng,fail}.tsv` | 台帳チェック。済=0 / 不一致=1 / 取得失敗=1 |
| `no_markers.md` | 出典記法を持たない14行。`refs_integrity` / `declared_counts` / `distribution` / `no_regression` が「測定できない」で NG |

「NG が出ない」を確認するだけでは検出器が壊れていても気づけない。
**欠陥を注入した版で NG が出ること**と、**前提を持たない文書で落ちること**まで見る。

```bash
./test_detectors.sh      # 0=全件一致 / 1=食い違いあり
```

検出器を足したら `CASES` に1行足す。
