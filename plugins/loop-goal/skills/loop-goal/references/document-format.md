# 文書の書式を1つ固定する — フェーズ0 を償却するために

**検出器を文書に合わせるのではなく、文書を検出器に合わせる。**

## 目次

1. なぜ
2. 書式 — 出典表を持つ / 本文の参照は `[S-01]` / 数字を含む断定には引用を添える /
   件数を申告するなら表で / 執筆経緯を本文に残さない
3. 使い方
4. この書式でも解けないもの

## なぜ

実測（2026-08-11）: ループ本体は自動で **1周 30,000〜38,000トークン・2〜3分**。
一方フェーズ0（書式採取 → 検出器の調整 → ゲートの取捨 → 凍結）は**人が判断する工程**で、
文書1本ごとに発生する。**自動の部分が安く、人の部分が高い。**

文書1本に1回しか回さないなら、フェーズ0 のコストは回収できない。
**書式を固定すれば、フェーズ0 は初回1回で済み、以後は使い回せる。**

同時に2つ解ける。

| 問題 | 書式を固定すると |
|---|---|
| 検出器が `[S-xx]` 記法に硬結合している | 硬結合が**前提**になるので問題でなくなる |
| ゲートが追跡可能性の形式しか測れない | 引用行を必須にすれば、第2層（原文照合）が効く |

2つ目が効く。実測で、根拠を5件足した版と1件も足していない版が同じゲートを通った。
**両者を分けたのは引用の有無だった。**

## 書式

この5つを守る。既定の検出器はこの書式で噛む。

### 1. 出典表を持つ

```markdown
## 出典

| ID | 出典 | Tier | 原文確認 |
|---|---|---|---|
| S-01 | Example Agency (2026-01-22) "Regional Adoption Survey" https://example.org/a | T1 | 済 |
| S-02 | Example Institute (2026-02) "Year-on-Year Trends" https://example.org/b | T2 | 未 |
```

- 行頭が `|`、1列目が `S-数字`（`refs_integrity` / `distribution` / `no_regression` が見る）
- **URL を同じ行に置く**（`span_verify` が出典と URL を結び付ける）
- `原文確認` 列は**人が書かない**。`span_verify` の台帳が根拠になる

### 2. 本文の参照は `[S-01]`

```markdown
対象地域における導入率は 42% であったと報告されている [S-01]。
```

### 3. 数字を含む断定には引用を添える

**ここが形式と実体を分ける。** 参照記号だけでは根拠が増えない。

```markdown
対象地域における導入率は 42% であったと報告されている [S-01]。

> The adoption rate in the target region reached 42 percent in 2025.
```

- 引用は `>` で始める（`no_regression` の `引用行` が数える）
- **原文のまま。** 訳さない・整えない・つなぎ合わせない。訳は引用の外に書く
- 逐語でないものを `>` で示さない。**言い換えは引用ではない**

**英語の出典を引くときの注意**（実験6 で判明）。既定の `SPAN` は `「」` を数えるため、
英文引用だけの文書では `引用スパン` が常時ゼロになり、**下限の指標が1つ死ぬ**。
対処は2つ。

| | 対処 | 副作用 |
|---|---|---|
| A | `no_regression.py` の `SPAN` を `「[^」]*」\|"[^"]*"` などに広げる | 本文中の引用符も拾う |
| B | そのまま使い、下限は「行数 / 引用行 / 出典参照 / 出典表」の4つで取る | 引用の中身が空になる書き換えを、引用行数が変わらなければ見逃す |

**既定は B。** A に広げるなら、広げた範囲で偽陽性が出ないか `clean.md` で確かめること。

### 4. 件数を申告するなら表で

```markdown
| 項目 | 件数 |
|---|---|
| 本文中の引用 | 12 |
| 取得不能(FETCH-FAIL) | 1 |
```

`declared_counts` が実測と突き合わせる。申告しないなら、この検出器をゲートから外す。

### 5. 執筆経緯を本文に残さない

「【訂正】」「初版では」「〜としていたが」は `forbidden_phrases` が落とす。
経緯は別ファイル（引き継ぎ書・調査ノート）に置く。

## 使い方

```bash
# 初回だけ: 噛み合いを確認する
python3 detectors/applicability_report.py 対象.md

# 毎回: ゲートを回す
cp 対象.md /tmp/base.md
BASE=/tmp/base.md ./gate.sh 対象.md

# ときどき: 引用が原文に実在するかを照合し、台帳に落とす（ループの外）
python3 detectors/span_verify.py 対象.md /tmp/gate/doc.verified
python3 detectors/spans_verified.py 対象.md /tmp/gate/doc.verified
```

## この書式でも解けないもの

書式を固定しても残る。**ゲートの緑をこれ以上の意味に読まないこと。**

- **言い換えの妥当性。** 参照先が当の主張を支えるかは機械では見ない（第4層）
- **過剰な付与。** 何件が適正かに客観的な根拠が無い。数字は出るが判定はしない
- **新規記述の真偽。** ループが足した記述の正しさは検査されない

実測では、参照43件のうち引用を伴うのは15件で、**28件は言い換えだけ**だった。
言い換え側は人か別工程（`verify-content` / `fact-checker`）が見るしかない。
