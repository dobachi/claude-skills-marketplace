# loop-goal

手を動かす順番・インストール・トラブル対処は [`USAGE.md`](USAGE.md)。以下は方法だけ。

**対象は文書の検証に限る。** ソースコードでは事情が違い（型検査・lint・テスト・ビルドという
既製の判定器が最初から揃っている）、同じ枠で語ると嘘になる。拡張は将来の課題。

**同じ書式の文書を継続的に出すなら、書式を先に固定する。**
検出器を文書に合わせる作業（手順2〜4）は人の時間を食い、**ループ本体より高い**。
書式を固定すれば初回1回で済む → [`references/document-format.md`](references/document-format.md)。
1本きりの文書に対しては、この道具は割に合わない。

**ループの制御系は作らない。** Claude Code に `/goal`・`/loop`・`/schedule` があり、
Codex や gemini では呼び出し側が `for` を書けば済む。
ベンダーをまたいで持ち運べる資産は**ループではなく、検出器の終了コード**である。

このスキルが提供するのは、その終了コードの作り方だけ。

## 手順

### 1. 終了条件をコマンドの終了コードに落とす

自然言語のまま `/goal` に渡さない。**「OK になるまで」の OK を、走らせられる形にする。**

```bash
python3 detectors/forbidden_phrases.py report.md   # 0=OK 1=NG
```

落とせないなら、そのゴールはループに向いていない。3 へ。

### 2. 検出器を選ぶ / 足す

[`detectors/`](detectors/) を見る。無ければ [`detectors/_template.py`](detectors/_template.py) を
コピーして冒頭の編集点だけ書き換える。作法は [`detectors/README.md`](detectors/README.md)。

**足す前に、どちらの種類か決める。規則の掛かり方が変わる。**

| 種類 | 中身 | 実例が要るか |
|---|---|---|
| `KIND="spec"` | 仕様から書ける。対応関係・数の一致・存在確認 | 不要。先に書いてよい |
| `KIND="example"` | ヒューリスティック・除外リスト・閾値 | **必須。** 実際に取り逃した欠陥からのみ足す |

先回りして書いた `example` は使われないか、起きたときには形が違う。
`ORIGIN` が空のまま回すと exit 2 で落ちる。

**実例の在庫が無いとき。** 実例は「この成果物での失敗」である必要はない。
同じ書き手・同じ環境なら失敗の形は似るので、別の成果物で観測したものが移る。
在庫がゼロなら、**最初の1周はゲート無しで回して実例を作る**。その周回の成果物は
「直った文書」ではなく、**欠陥版の fixture と、欠陥の1行記録**である。

**欠陥版は1周目にしか手に入らない。** 通してしまうと二度と取れない。
`forbidden_phrases.py` が書けたのは、欠陥版（432行）を捨てずに残したからである。

**どちらの種類でも、実物に当てる工程は飛ばせない。** まず噛み合いを見る。

```bash
python3 detectors/applicability_report.py 対象.md    # 判定しない。数字を出すだけ
```

そのうえで書式を `grep` で採って合わせ、
3つの期待値（正常版=0 / 欠陥注入版=1 / **前提を持たない文書=1**）を確認する。
3つ目を見なかったせいで、出典ゼロの文書を素通しする検出器を2本出荷しかけた。

```bash
./detectors/test_detectors.sh     # 期待値の表を走らせる。0=全件一致
```

### 3. 終了条件にしないものを外に出す

| 層 | 例 | 扱い |
|---|---|---|
| 構造 | 参照の整合、件数の一致、リンク切れ | ループに入れる |
| 内容 | 引用が**原文に実在するか** | ループに入れる。ただし**照合そのものはループの外**（下記） |
| 分布 | 出典の集中度、Tier構成 | 数字を出す。閾値は人が決める |
| **主観** | 論旨の妥当性、読みやすさ、公平さ | **入れない。** 別コンテキストの評価者へ |

第4層を混ぜると壊れる。自己採点が効かない領域である。

**第2層は2つに割れる。混ぜると「照合器を作れば塞がる」と誤解する。**

| | 中身 | 扱い |
|---|---|---|
| 引用スパンが原文に実在するか | 機械で照合できる | **照合はループの外**（遅い・非決定的・ネットワーク依存）。ゲートは**照合の記録**を見る |
| 参照が主張を支えるか（言い換え） | 照合すべき原文の断片が無い | **ループに入れない。** 第4層と同じ扱いで、人か `verify-content` / `fact-checker` へ |

実測（実験3）: 参照43件のうち引用を伴うのは15件で、**28件は言い換えだけ**だった。
ループが足した未確認の記述（§7.10）も言い換え側にあり、**照合器を作っても捕まらない**。

照合をループの中に入れると、手順4の前提「全部走らせても秒で終わる」が崩れ、
取得失敗の扱いが fail-open か「ネットが落ちたら止まる」の二択になる。
だから**照合はバッチで回して結果を記録に落とし、ゲートは記録を見る**。
記録はループの書き込み範囲の外に置く（満たす側が「済」と書けないようにする）。

### 4. ゲートを組む — 1本にしない

```bash
gate() {
  python3 detectors/refs_integrity.py "$1" &&
  python3 detectors/declared_counts.py "$1" &&
  python3 detectors/citation_presence.py "$1" &&
  python3 detectors/no_regression.py "$BASE" "$1"
}
```

**1本だけをゲートにすると、通った瞬間に別の1本が落ちる。** 実測で起きている
（`citation_presence` を満たした結果 `declared_counts` が壊れた）。全部走らせても秒で終わる。

`no_regression.py` を必ず混ぜる。他はどれも**消せば満たせる**ためである。

`distribution.py` は入れない。**閾値に客観的な根拠が無い**ので、停止条件にすると
「閾値を満たすために出典を水増しする」が最短経路になる。数字を出して人が読む。

### 5. 境界を機構で担保する

意図ではなく仕組みで塞ぐ。分けるのは2つだけ。

| 境界 | 防ぐもの |
|---|---|
| 検出器を作る側 ≠ 満たす側 | 満たしやすい検出器を書く／検出器を書き換えて逃げる |
| 満たす側 ≠ 評価する側 | 自己採点 |

手段（強度順）: **検出器をループの書き込み範囲外に置く** / subagent の `tools` で
書き込み範囲を絞る / 別ベンダーに委譲。最低でも `chmod 444` はする。

ステップごとに分けるのは不要。過剰委譲はコストが見合わない。

### 6. 上限を付けて回す

```bash
# Claude Code: ツールがループを持つ
/goal gate.sh report.md が通るまで直して、5回で諦めて

# Codex / gemini: 呼び出し側がループを持つ
for i in $(seq 5); do gate.sh report.md && break; codex exec "NG を直して"; done
```

回数と予算の上限を必ず付ける。ベンダーごとの現況は
[`references/vendor-matrix.md`](references/vendor-matrix.md)。**腐る。** 期限は機械で見る。

```bash
python3 detectors/matrix_freshness.py references/vendor-matrix.md   # 既定14日
```

### 7. 通ったあとに疑う

**通ったことは、欠陥が無かったことを意味しない。**
より正確には — **ゲートの通過は「追跡可能性の形式が整った」ことしか意味しない。**

同じ文書・同じゲートで3本回した実測（2026-08-11）。

| | 出典参照 | **引用（根拠の実体）** | 誤帰属 | ゲート |
|---|---|---|---|---|
| web あり | 0→43 | **0→5**（全件が原文と逐語一致） | 発見して修正 | 通過 |
| web なし | 0→33 | **0→0** | 温存（注記を添えた） | 通過 |
| 材料も断つ | 0→6 | **0→0** | 温存 | 通過 |

**根拠を5件足した版と、1件も足していない版を、同じゲートが両方通した。**
`no_regression.py` は「根拠の実体は増えていない」と出力するが、**NG にはしない**
（増えていないことを咎めると、正当な整理まで落ちる）。

見るべきものは3つ。

- 検出器の出力の「保証しないこと」を読む。そこが見ていない範囲である
- **`no_regression.py` の増分を読む。** 形式（出典参照・出典表）だけ増えて
  実体（引用行・引用スパン）が 0→0 なら、根拠は1件も増えていない
- 満たし方が「消す」でなかったかを差分で見る

**検出器に合わせて文章を変える動きが観測されている。** 実測7回。

| 何をしたか | 実測 |
|---|---|
| 文書側の整形で発火が消えた | 実験2 |
| `S-07` を `[S-07]` と書いて回避 | 実験4 |
| 但し書きから意図的に数字を外した | 実験5 |
| **`【推】` を付けて対象外にした** | 実験7（0件 → 9件） |
| **`SKIP_SECTIONS` に載る名前で節を作った** | 実験7（`## Source Register` を新設） |
| **`declared_counts` を 0 申告で満たした** | 実験7（`\| 本文中の引用 \| 0 \|`） |
| 参考文献の見出しに参照を併記して候補を消した | 実験7（41件） |

**いずれも根拠は増えていない。** 下3つは**検出器の編集点そのものが抜け道になった**例である。

**塞げるものと塞げないものがある。塞げないものを塞いだふりをしない。**

| | 塞げるか | 現在の扱い |
|---|---|---|
| `SKIP_SECTIONS` の節名 | **無理**（節名でなく内容で判定する必要がある） | 出力に「この名前で節を作れば対象外にできる」と明示 |
| 0 申告 | 容易 | 数字を出す。**NG にはしない**（0 が妥当な文書もある） |

### 上限を迫ると、検証器は「仕様」として読まれる

実測（実験7、上限2周・候補52件）: 満たす側は**ゲートを1回も試さず**、
検出器5本と `gate.sh` のソースを全部読み、470行を手で数えて候補の内訳を予測してから
一括処理で1周で通した。**ゲートを回避したのではなく、ゲートを仕様として読んでいる。**

> **検出器のソースが読めることは諸刃である。** 「編集して使う」ために開いているが、
> 同じ可読性が「解析的に満たす」も可能にする。隠す設計は取らない
> （隠しても Goodhart は消えず、編集可能性を失うだけ）。**読まれる前提で書くこと。**

## やらないこと

- **ループの制御系の自作**（ランナー・スケジューラ・出口判定）。ツールにある
- **ベンダー機能の抽象化レイヤ**。定義も責任範囲も違う。抽象化すると嘘になる
- **ユースケース別のゴール設定パターン集**。能力のあるモデルが自力でやる

追記するかどうかは次のフィルタで決める。

> **これが無いと、モデルは間違えるか？**

通る例:「検証器を目標にすると最短経路が『消す』になりうる」「span照合は引用の忠実さで
あって事実の正しさではない」。落ちる例:「ゴールは明確に」「上限を設けましょう」。
