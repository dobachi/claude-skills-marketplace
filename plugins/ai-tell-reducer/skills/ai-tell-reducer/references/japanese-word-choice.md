# 日本語のAIっぽさ：語の選び方（和語の転用・借り物の語・見出し）

文法も構文も正しく、翻訳調でもないのに、語の選び方だけが浮いている文がある。「この分類が見直しに効く」「例外規定を本則の中に畳む」「交渉が座礁する」のような文である。一つひとつは日本語として成立するが、報告書や解説書の地の文で全章にわたって繰り返されると、書き手の癖ではなくモデルの癖として読まれる。

このファイルは、その「語の選び方」を扱う。`japanese-translationese.md` が英語の構文の残りを扱うのに対し、ここは日本語の語彙の中での選び違いを扱う。判定の拠り所として、文化審議会「公用文作成の考え方」（2022年1月7日建議）を使う。

各項目は「症状 → なぜ不自然か → 判定 → 直し方」。**元文にない事実・数字・固有名詞は足さない**（SKILL.md のガードレール）。

## 1. 和語の比喩的な転用

**症状**：日常の和語動詞・和語名詞を、抽象的な対象に比喩として当てる。「〜に効く」「畳む」「（軸に）載せる」「寄せる」「握る」「落とし込む」「回す」「引き取る」「束ねる」「降ろす」「立て付け」「手触り」「地続き」。

**なぜ不自然か**：どれも意味の幅が広く、読み手が文脈から意味を補う必要がある。「畳む」は含めるのか、統合するのか、廃止するのか。会話なら通じるが、定義や判定を述べる文では正確さが落ちる。一回なら書き手の味として読めるが、同じ語が何十回も出ると癖として目に付く。

**判定**：字義どおりの動詞か漢語に置き換えて、意味が通るかを見る。通るなら、元の語は意味を運んでいなかった。「公用文作成の考え方」は次のように整理している。

- 「日常では別の意味で使われる語は、混同を避けるようにする」（Ⅱ-4 ウ）
- 「重厚さや正確さを高めるには、述部に漢語を用いる」（Ⅱ-5 ウ）
- 「分かりやすさや親しみやすさを高めるには、述部に訓読みの動詞を用いる」（Ⅱ-5 エ）

つまり和語動詞そのものが悪いのではない。定義・判定・条件を述べる箇所は漢語に、手順や説明をやわらかく述べる箇所は和語に、という使い分けの問題である。全部を漢語にすると今度は硬すぎる。

**直し方**：その文で実際に言いたい動作を一つに決めて書く。

| 転用 | 言いたいこと（文脈で選ぶ） |
|---|---|
| 〜に効く | 〜で決まる／〜に使える／〜を左右する／〜に有効である |
| 畳む | 含める／統合する／廃止する |
| 軸に載せる | 軸として扱う／軸に含める |
| 〜に寄せる | 集約する／統一する／近づける |
| 握る | 管理する／保有する／決定権を持つ |
| 落とし込む | 反映する／具体化する |
| 回す | 運用する／繰り返す／実行して見直す |
| 引き取る | 扱う／担当する／引き継ぐ |
| 降ろす | 通達する／示す／展開する |

Before：旧版の規程は、例外の扱いを本則の中に畳んでいる。
After：旧版の規程は、例外の扱いを本則に含めている。

Before：対象外とする範囲にも、この分類が効く。
After：対象外とする範囲も、この分類で決まる。

**残すもの**：文書全体で一貫して使っている比喩の一部。たとえば冒頭で「処方箋」の比喩を立て、「効く施策／効かない施策」と対で使い続けているなら、それは著者が選んで組み立てたものなので残す。同じ「効く」でも、その枠の外で「この分類が見直しに効く」と使った箇所だけを直す。

## 2. 借り物の比喩・他分野の語

**症状**：主題と関係のない分野から語を借りる。「座礁する」（海事）「着火する」（燃焼）「本丸」（城）「旗を振る」「物差し」「見取り図」「橋渡し」「土台」「触媒」（化学反応）。`expression-and-stance.md` の E6 が扱う「羅針盤」「架け橋」と同じ根だが、こちらは派手さがないぶん見逃しやすい。

**なぜ不自然か**：読み手は比喩を一度ほどいてから意味を取る。しかも多くは、別の主題の文書にそのまま持っていける。「公用文作成の考え方」の解説は、分かりやすくしようとして「誤解を招きやすいたとえや比喩を用いる」と正確さが損なわれる、と注意している（解説 Ⅰ-1 カ）。

**判定**：strip（比喩を外して具体的な中身が残るか）と swap（別の主題にもそのまま使えるか）。SKILL.md の The tests と同じ。

**直し方**：比喩を外し、何がどうなるのかを書く。別の比喩に取り替えない。

Before：条件を詰めないまま始めた交渉は、たいてい座礁する。
After：条件を詰めないまま始めた交渉は、たいてい途中で行き詰まる。〔どこで止まるかが元文にあれば、それを書く〕

Before：補助金は需要に着火するが、持続はさせない。
After：補助金は購入のきっかけになるが、継続の理由にはならない。

**残すもの**：その文書が用語として定義し、一貫して使っている語（次の 4 を参照）。分野で定着した言い方（「ボトルネック」「サイロ」）。

## 3. 文になった見出し・論点を示さない見出し

**症状**：二つの型がある。

- **文になった見出し**：「この分類が見直しに効く」「制約は動く」「全部門を一度に揃える計画は、座礁する」。無生物の主語に和語動詞や比喩を続けた短文。英語の解説記事の見出し（"Why this definition matters"）を移した形で、目次に並ぶと目立つ。
- **論点を示さない見出し**：「〜について」「〜の重要性」「概要」。何を述べる節かが分からない。

**判定**：「公用文作成の考え方」（Ⅲ-2）の基準を使う。

- 「分量の多い文書では、見出しを活用し、論点を端的に示す」
- 「見出しを追えば全体の内容がつかめるようにする」

見出しだけを抜き出して上から読み、内容がつかめるかを見る。`scripts/dict_scan.py --headings` が見出しを一覧し、文の形のものに印を付ける。

文の形であること自体は欠点ではない。「審査は省略できるが、記録は省略できない」のように、主張をそのまま述べた見出しは、目次だけで内容が伝わる。直すのは、**文の形なのに述語が比喩や転用で、主張が読み取れないもの**である。

**直し方**：節の中身を一文で言い、それを見出しにする。体言止めにするか平叙文にするかは、文書内で揃える。

Before：### この分類が見直しに効く
After：### この分類で見直しの対象と順序が決まる
（体言止めに揃えるなら）### 分類による見直し対象の判定

Before：## 相互運用性について
After：## 相互運用性の判定基準

節の中身を読まずに見出しだけを言い換えない。中身と見出しが合っていないと分かった場合は、見出しを中身に合わせるか、`[要著者判断]` として挙げる。

## 4. 語ごとの扱いを決める（三択）

候補の語は、消すか残すかの二択ではない。「公用文作成の考え方」は専門用語の扱いを三つに分けている（Ⅱ-2）。同じ三択を、文書が独自に使う語にも当てはめる。

| 扱い | どういう語か | すること |
|---|---|---|
| 言い換える | 意味を運んでいない転用・比喩 | 字義どおりの語に置き換える |
| 説明を付けて使う | 文書の議論に必要で、読み手が知らない語 | 初出で定義し、用語集に載せ、以後は同じ意味だけで使う |
| そのまま使う | 分野で定着した語、著者が選んだ言い回し | 手を付けない |

「説明を付けて使う」に入れた語は、**定義した意味以外で使わない**。「制約工程」を用語として定義したなら、「制約は動く」のように定義から離れた使い方は言い換える。

この三択は著者の判断である。どの語を用語として残すかを、こちらで決めない。候補と件数を示して著者に尋ね、答えを受けて直す（SKILL.md の Workflow 3）。

## 5. 長い文書での進め方（台帳と言い換え表）

数千行の文書では、通読だけでは同じ語の扱いが章ごとにずれる。出版・翻訳の実務で使われてきた「用字用語の統一」（表記統一リスト）と同じ手順を取る。

1. **候補を洗い出す。** `scripts/dict_scan.py <ファイル> --summary` で、どの語が何回出ているかを見る。回数は判定ではなく、どこから見るかの手がかりである。辞書に無い語は拾えないので、見出しは `--headings` で全件を見て、本文は章ごとに通読する。
2. **台帳にする。** `--format tsv` が、出現箇所ごとに判断欄（`decision`）のある表を出す。語ごとに 4 の三択を決める。
3. **言い換え表と許可リストに書く。** 言い換えると決めた語で同梱辞書に無いものはプロジェクト辞書（`.ai-tell-dict.ini`）に、残すと決めた語句は許可リスト（`.ai-tell-allow.txt`）に書く。次回から、残すと決めた箇所は候補に出なくなる。
4. **章単位で直す。** 直すのは表現だけで、主張・数値・引用は動かさない。機械的に一括置換しない。同じ語でも、文脈で言いたいことが違う。
5. **再発を防ぐ。** 加筆のたびに `dict_scan.py` を回す。プロジェクトが textlint を使っているなら、確定した言い換えを prh の辞書（`prh.yml`）に写してもよい。

書式と、プロジェクト辞書から同梱辞書へ語を昇格させる基準は `dictionary.md` にある。

## 6. 作業の呼び名

依頼の範囲を取り違えないために、呼び名を区別する。

| 呼び名 | すること | このスキルとの関係 |
|---|---|---|
| 推敲 | 書き手が表現を練り直す | このスキルの仕事 |
| 校正 | 誤字脱字・表記の誤りを正す | 範囲外。見つけたら報告にとどめる |
| 校閲 | 事実・固有名詞・数値・引用を確かめる | 範囲外。`verify-content` / `fact-checker` の仕事 |
| 用字用語の統一 | 同じ内容を同じ語・同じ表記で書く | 5 の言い換え表がこれに当たる |

## 7. 過剰修正に注意

- **和語を一掃しない。** 手順や説明の文まで漢語にすると、公用文の悪い例のように硬くなる。直すのは、定義・判定・条件を述べる箇所で意味が曖昧な語だけ。
- **一括置換しない。** 「効く」を全部「有効である」にすると、新しい一様さができる。箇所ごとに言いたいことを決める。
- **著者の組み立てた比喩を壊さない。** 冒頭で立てて文書全体で使っている比喩は、著者の選択である。
- **用語を言い換えない。** 文書が定義した語、分野で定まった語は残す。
- **見出しを体言止めに揃えすぎない。** 主張を述べた文の見出しは、目次で内容が伝わる。直すのは主張が読み取れないものだけ。
- **辞書に当たったから直す、をしない。** 辞書は場所を示すだけである。当たった箇所でも、判定を通れば残す。
