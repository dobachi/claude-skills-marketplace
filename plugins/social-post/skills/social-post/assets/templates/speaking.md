# 1. 事前告知

読者に必要なのは、日時・場所・何の話か・自分に関係あるか。宣伝文句ではない。

```
<何の話をするかを1行で。日時ではなく内容から入る。例: <会議名>で、制御方式の
選定基準について話します。<月日><時刻>、<会場・オンライン>です。>

<誰に向けた話か、何を持ち帰れるかを1〜2文>

<関連する自分の背景を1文（信頼の根拠。自慢ではなく事実）>

<CTA: 参加登録リンクは1stコメント／会場にいる方は声をかけてください>

———
(English below)

<Independent English version. Talk topic first, then when and where.>

#<会議名> #<分野>
```

事前告知の注意:
- 開催の1〜2週間前と前日の2回まで。連投しない。
- 「ぜひご参加ください！」だけの投稿にしない（内容がないと宣伝に見える）。
- 共同登壇者・主催者を名前で挙げる。

# 2. 事後報告

来られなかった人に、中身を渡す投稿。「登壇しました」は情報ではない。

```
<話した内容の結論を1行で。例: <会議名>で、制御方式の選定は3つの条件で決まる
という話をしました。>

<いちばん反応があった論点、または質疑で出た指摘を1〜2文。ここが本体>

<自分がその場で更新した考えを1〜2文>

<CTA: 資料は1stコメント／同じ課題の方と話したい>

———
(English below)

<Independent English version, same structure.>

#<会議名> #<分野>
```

事後報告の注意:
- **受けた質問・指摘を1つ書く**。称賛だけの報告は読む価値がない。
- 資料を公開する場合、社内・主催者の公開可否を確認。
- 写真を使う場合は、聴衆の顔が特定できないもの。撮影者のクレジット。

# フック代替3案（各140字以内、事後報告用）

1. 指摘から: `<例: 発表後に受けた指摘が、いちばんの収穫でした。>`
2. 結論から: `<例: 選定は結局3つの条件で決まる、という話をしてきました。>`
3. 更新から: `<例: 発表前に考えていた前提が、質疑で1つ崩れました。>`
